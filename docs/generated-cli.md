# Generated CLI Guide

## Structure

Every CLI generated by FuseCLI follows the same structure:

```
<app>-cli/
├── src/
│   ├── index.ts           # Entry point (Commander.js)
│   ├── commands/
│   │   ├── auth.ts        # auth set/show/test/remove
│   │   ├── users.ts       # Auto-generated resource commands
│   │   └── projects.ts    # One file per resource
│   ├── schemas/
│   │   ├── users.ts       # Zod validation per resource
│   │   └── projects.ts
│   └── lib/
│       ├── client.ts      # HTTP client (fetch + retry)
│       ├── auth.ts        # Token storage (chmod 600)
│       ├── output.ts      # JSON envelope + text table
│       ├── errors.ts      # CliError + exit codes
│       └── config.ts      # Constants (BASE_URL, AUTH_TYPE, etc.)
├── SKILL.md               # Agent discovery
├── package.json           # commander + zod only
└── tests/                 # Unit + integration tests
```

## Authentication

### Set a token

```bash
myapi-cli auth set "your-api-key"
```

Stored at `~/.config/fusecli/tokens/<app>-cli.txt` with permissions `600`.

### Show token (masked)

```bash
myapi-cli auth show
# sk_l...wxyz

myapi-cli auth show --raw
# sk_live_full_token_here
```

### Test token

```bash
myapi-cli auth test
# Token is valid.
```

### Remove token

```bash
myapi-cli auth remove
```

## Command Patterns

### Multi-action resources

When a resource has multiple endpoints (list, get, create, delete):

```bash
myapi-cli users list --json
myapi-cli users get <id> --json
myapi-cli users create --name "John" --email "john@test.com" --json
myapi-cli users delete <id> --json
```

### Single-action resources (flattened)

When a resource has only one endpoint (like a search endpoint), the command is flattened — no subcommand needed:

```bash
# Instead of: myapi-cli search search --query "test"
# You get:    myapi-cli search --query "test"
myapi-cli search --query "test" --json
```

## Output Formats

### JSON (default for agents)

```bash
myapi-cli users list --json
```

```json
{
  "ok": true,
  "data": [
    { "id": "1", "name": "John", "email": "john@test.com" }
  ]
}
```

### Text (default for humans)

```bash
myapi-cli users list
```

```
id    name    email
1     John    john@test.com
2     Jane    jane@test.com
```

### CSV

```bash
myapi-cli users list --format csv
```

```
id,name,email
1,John,john@test.com
2,Jane,jane@test.com
```

## Error Handling

### JSON errors

```bash
myapi-cli users get nonexistent --json
```

```json
{
  "ok": false,
  "error": {
    "code": 404,
    "message": "Not Found"
  }
}
```

### Exit codes

| Code | Meaning |
|------|---------|
| 0 | Success |
| 1 | API Error (HTTP 4xx/5xx) |
| 2 | Usage Error (bad arguments) |
| 3 | Auth Error (no token configured) |
| 4 | Network Error (timeout, DNS) |
| 5 | Parse Error (invalid spec) |

## HTTP Client

The generated client includes:

- **Retry**: 3 retries with exponential backoff on 429 (rate limit) and 5xx
- **Timeout**: 30 seconds per request
- **Auth injection**: Token automatically added to every request
- **JSON parsing**: Responses parsed as JSON with fallback to text
- **MCP support**: If BASE_URL ends with `/mcp`, the client sends JSON-RPC instead of REST

## Auto-Generated SKILL.md

Every CLI comes with a SKILL.md that includes:

- **Frontmatter** — name, description, version for agent discovery
- **Commands** — every command with `--flags`, descriptions, required/optional, examples
- **Workflows** — auto-detected producer→consumer chains based on parameter semantics
  - Params like `--query` → entry point (search, filter)
  - Params like `--id`, `--url` → consumer (needs result from another command)
  - Example: `search --query "react" → context --library-id "/facebook/react"`
- **Exit codes** — standard codes for agent error handling

The SKILL.md is 100% dynamic — different APIs produce different content, commands, and workflows.

## Standalone

Generated CLIs have **zero** `@fusecli/*` dependencies. The only dependencies are:

- `commander` ^14.0.0 — CLI framework
- `zod` ^4.0.0 — Runtime validation
- `picocolors` ^1.1.0 — Terminal colors

Total size: ~100KB bundled.
