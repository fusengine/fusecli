```markdown
# FuseCLI Expert Agent

You are an expert in using FuseCLI to generate, manage, and use CLI tools
that wrap REST APIs. You help users and other agents interact with external
APIs through standardized CLI commands.

## When to Activate

- User mentions needing to access an external API
- User mentions a specific service (Typefully, Stripe, Linear, etc.)
- Another agent needs to call an external API during a task
- User asks to "create a CLI" or "wrap an API"

## Decision Flow

1. Check if CLI exists: `fusecli list --json`
2. If exists → use it directly via Bash
3. If not → check registry: `fusecli search <api> --json`
4. If found → `fusecli install <api>`
5. If not found → find OpenAPI spec → `fusecli create <api> --openapi <url>`
6. Always verify: `<api>-cli auth test --json`
```

```markdown
# Create CLI from OpenAPI

## When to Use
When the user wants to create a new CLI tool from an API's OpenAPI spec.

## Steps
1. Find the OpenAPI spec URL (ask user or search API docs)
2. Run: `fusecli create <app> --openapi <url>`
3. Run: `fusecli bundle <app>`
4. Run: `fusecli link <app>`
5. Verify: `<app>-cli --help`
6. Configure auth: `<app>-cli auth set <token>`

## Example
\`\`\`bash
fusecli create typefully --openapi https://api.typefully.com/openapi.json
fusecli bundle typefully
fusecli link typefully
typefully-cli auth set "typ_xxx"
typefully-cli drafts list --json
\`\`\`
```

```markdown
# Runtime API Call

## When to Use
- Quick one-off API call
- Testing an API before committing to CLI generation
- Agent needs to call an API it hasn't seen before

## Command
\`\`\`bash
fusecli run --openapi <url> <resource> <action> [options] --json
\`\`\`

## Example
\`\`\`bash
# Instant access — no install needed
fusecli run --openapi https://api.example.com/spec.json users list --json
fusecli run --openapi ./local-spec.yaml orders get ord_123 --json

# Discover available resources
fusecli run --openapi ./spec.json --help
\`\`\`
```

## Cross-Agent Collaboration Patterns

### Pattern 1: Agent Needs API Data During Task

```
User: "Crée une page Next.js qui affiche mes drafts Typefully"

nextjs-expert thinks: "I need Typefully API data to understand the schema"
nextjs-expert calls: Bash("typefully-cli drafts list --json --limit 1")
nextjs-expert receives: { "ok": true, "data": [{ "id": "...", "content": "...", "status": "..." }] }
nextjs-expert now knows: the exact response shape → generates correct TypeScript types
nextjs-expert writes: page.tsx with proper types, TanStack Query hook, etc.
```

### Pattern 2: Agent Creates CLI On-the-Fly

```
User: "Publie un post sur mon compte DEV.to"

Claude Code thinks: "No dev-to-cli found. Let me check..."
Claude Code calls: Bash("fusecli list --json")
→ Not found
Claude Code calls: Bash("fusecli search dev.to --json")
→ Not in registry
Claude Code thinks: "I need to find the OpenAPI spec"
Claude Code searches: Exa("dev.to api openapi specification")
→ Found: https://developers.forem.com/api/v1/openapi.json
Claude Code calls: Bash("fusecli create devto --openapi https://developers.forem.com/api/v1/openapi.json")
Claude Code calls: Bash("fusecli bundle devto && fusecli link devto")
Claude Code calls: Bash("devto-cli articles create --json --title 'My Post' --body '...'")
→ Done!
```

### Pattern 3: Sniper Validates API Integration Code

```
User made changes to API integration code

sniper agent runs its 6-phase validation:
1. explore-codebase → finds API calls in the code
2. research-expert → checks API docs
3. grep usages → finds all `typefully-cli` calls in the project
4. Bash("typefully-cli auth test --json") → verifies auth still works
5. Bash("typefully-cli drafts list --json --limit 1") → verifies endpoint accessible
6. Reports: "API integration validated — all endpoints responding"
```

### Pattern 4: Design Expert Generates API-Connected UI

```
User: "Crée un dashboard pour voir mes stats Stripe"

design-expert generates: UI layout via Gemini Design MCP
nextjs-expert wires data:
  Bash("stripe-cli charges list --json --limit 100")
  Bash("stripe-cli customers list --json")
  Bash("stripe-cli balance get --json")
  → Uses response schemas to generate TanStack Query hooks
  → Types are exact because --json envelope is predictable
```

## SKILL.md Auto-Linking

When `fusecli link <app>` runs, it auto-detects agent directories:

```typescript
// packages/cli/src/lib/agents.ts
export const AGENT_SKILL_DIRS: Record<string, string> = {
  "claude-code": "~/.claude/skills",
  "codex-cli": "~/.codex/skills",
  "cursor": "~/.cursor/skills",
  "windsurf": "~/.windsurf/skills",
  "cline": "~/.cline/skills",
  // Fusengine custom agents
  "fusengine": "~/.claude/plugins/cache/fusengine-plugins/.skills",
};

export function detectAgentDirs(): string[] {
  return Object.values(AGENT_SKILL_DIRS)
    .filter(dir => existsSync(expandHome(dir)));
}
```

For each detected directory, `fusecli link` creates:
```
<agent-skills-dir>/<app>-cli/SKILL.md → symlink to generated SKILL.md
```

## Integration with Existing Fusengine Skills

```bash

/fuse-commit-pro:commit
# → Detects: "feat: add my-api CLI wrapper"
# → Includes: generated resource files + SKILL.md
```

### Security Integration (fuse-security)

```bash
# fuse-security:scan can audit generated CLIs
# Checks:
# - Token storage permissions (chmod 600)
# - No secrets in generated code
# - HTTPS-only base URLs
# - Input validation (Zod schemas present)
# - Auth header not leaked in logs
```

### SOLID Integration (fuse-solid)

Generated CLIs follow SOLID rules automatically:
- Every file < 90 LOC (enforced by plugin-cli generator)
- Interfaces separated in `src/interfaces/`
- Auth strategies implement IAuthStrategy
- Output formatters implement IOutputFormatter
- JSDoc on every exported function
